# Notes for Claude

- Project context (features, settings, behavior, project structure) lives in `PROJECT.md`. Read it for context, and keep it up to date whenever a feature or the structure changes.
- `README.md` only covers how to develop: the commands and a short line for each. Keep it short.
- Localization: every user-facing string must be localized in the same change that adds or edits it, in every supported language, with no exceptions and no follow-up PRs. A string is user-facing if it can appear on screen (labels, buttons, menus, alerts, help tooltips, placeholders, Event Viewer text). Log messages and identifiers are not localized.
  - How: add the English text as a line in every `Resources/Localization/<language>.lproj/Localizable.strings` (the key is the English text, with `%@` for interpolated strings and `%lld` for integers), translated. Literal text in SwiftUI (`Text("…")`, `Button("…")`, `.help("…")`) is translated on its own; text built in code uses `String(localized: "…")`; a key known only at run time uses `localized(_:)`. Text that must never be translated uses `Text(verbatim:)`.
  - Then run `python3 scripts/check-localization.py`; it must report 0 problems before committing.
- Every settings pane except General, Remap and Developer ends with a **Reset to Defaults** button. When adding a setting, include it in that pane's `reset()`. Resets leave on/off switches, excluded apps, history and Open at login alone.
- Every settings row also gets a right-click **Reset to Default** with `.resetMenu(...)` (`Settings/ResetMenu.swift`), taking its default from the settings class's constants, the same ones `reset()` uses. Add it to any new row.
- Changes that matter to people using Estris add a short line under **Unreleased** in `CHANGELOG.md`, in the same change, written for users: a new utility or feature, a new or changed setting or default, a fix for something they would have run into, a change in how something they use behaves. Leave out small polish and details of installing, updating or permissions (a window opening on another screen, the disk image ejecting itself), and anything internal (refactors, docs, the website, build and release scripts). When unsure, leave it out.
- A new utility also goes on the website (`web/`) in the same change: its entry in `web/src/data/features.ts` (title, tagline, details, length, accent and icon), an animation in `web/src/components/spots/` registered in `index.ts`, made like the others with the helpers in `web/src/lib/motion.ts` and showing the utility doing what it does, and its video recorded into `web/public/spots/` (`npm run build && npm run render-spots -- <id>`; check the frames first with `--sheet`). Then run `npm run render-og` too, as the shared picture says how many tools there are.
