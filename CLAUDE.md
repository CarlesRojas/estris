# Notes for Claude

- Estris is a monorepo with two native apps: `macos/` (Swift) and `windows/` (C#, WinUI 3), plus `web/`. Every feature, change or fix goes into both apps in the same change, even when the request only mentions one. The exception is what makes no sense on a platform, because the system already does it well or it can't really be done there: then it stays out of that app, the table in `PROJECT.md` says so, and you tell the user. Don't build a lesser version just to have it.
- The Windows app must look like a Windows app, not a Mac port: Fluent style, Mica and Acrylic, Segoe Fluent Icons, the system accent colour.
- Project context lives in `PROJECT.md` (the two apps, what each has, releases, website), `macos/PROJECT.md` and `windows/PROJECT.md` (features, settings, behavior, structure). Read them for context, and keep them up to date whenever a feature or the structure changes.
- `README.md` only covers how to develop: the commands and a short line for each. Keep it short.
- Localization: every user-facing string must be localized in the same change that adds or edits it, in every supported language, with no exceptions and no follow-up PRs. A string is user-facing if it can appear on screen (labels, buttons, menus, alerts, help tooltips, placeholders, Event Viewer text). Log messages and identifiers are not localized.
  - Mac: add the English text as a line in every `macos/Resources/Localization/<language>.lproj/Localizable.strings` (the key is the English text, with `%@` for interpolated strings and `%lld` for integers), translated. Literal text in SwiftUI (`Text("…")`, `Button("…")`, `.help("…")`) is translated on its own; text built in code uses `String(localized: "…")`; a key known only at run time uses `localized(_:)`. Text that must never be translated uses `Text(verbatim:)`. Then run `python3 macos/scripts/check-localization.py`.
  - Windows: visible text goes through `T("…")` (`Core/Loc.cs`), with the same keys, and is translated in `windows/src/Estris/Localization/<language>/<area>.strings` (English has no file). Then run `python windows/scripts/check-localization.py` (`--from-mac` copies what the Mac already has).
  - Each check must report 0 problems before committing.
- Every settings pane except General, Remap and Developer ends with a **Reset to Defaults** button. When adding a setting, include it in that pane's `reset()` (Mac) or `pane.ResetButton` (Windows). Resets leave on/off switches, excluded apps, history and Open at login alone.
- Every settings row also gets a right-click **Reset to Default**. Mac: `.resetMenu(...)` (`Settings/ResetMenu.swift`), taking its default from the settings class's constants, the same ones `reset()` uses; add it to any new row. Windows: rows built with `Pane` from a `Setting<T>` have it already; a custom row calls `Pane.WithReset`.
- Changes that matter to people using Estris add a short line under **Unreleased** in `macos/CHANGELOG.md` and `windows/CHANGELOG.md`, in the same change, written for users: a new utility or feature, a new or changed setting or default, a fix for something they would have run into, a change in how something they use behaves. Leave out small polish and details of installing, updating or permissions (a window opening on another screen, the disk image ejecting itself), and anything internal (refactors, docs, the website, build and release scripts). When unsure, leave it out.
- A new utility also goes on the website (`web/`) in the same change: its entry in `web/src/data/features.ts` (title, tagline, details, length, accent and icon, with `windowsDetails` where the wording differs on Windows, or `macOnly`), an animation in `web/src/components/spots/` registered in `index.ts`, made like the others with the helpers in `web/src/lib/motion.ts` and showing the utility doing what it does, and its video recorded into `web/public/spots/` (`npm run build && npm run render-spots -- <id>`; check the frames first with `--sheet`).
